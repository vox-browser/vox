## Boundaries of the translations

- **LibJS:** the browser still defaults to JavaScriptCore. These fixes improve
  Vox's translated VM/parser/regex owners. The surrogate-boundary port does not
  supply the absent RegExp `lastIndex` host layer; literal-key tests establish
  parser behavior without claiming complete destructuring bytecode support.
- **MathML:** this batch adds `a[href]` link matching and UA styling. Navigation,
  focus and URL handling are separate work.
- **Audio decoding:** rates are checked at the existing WAV/FFmpeg WebAudio
  boundaries. The **512 MiB limit is a decoded sample/output budget**; native
  interleaved data and planar copies can coexist. The upstream MediaServer pool
  and channel-transfer freeing are not duplicated. Native FLAC/Ogg/AAC header
  parsers and HTML playback remain host-library owners.
- **MediaSource:** strings are capped at 16 KiB and codec configurations at
  16 MiB. Vox retains the complete ISO sample entry, so its cap includes entry
  overhead and unknown child boxes. Quota accounting includes configuration
  copies introduced by eviction/splitting. Upstream's fallible-clone allocation
  error path has no corresponding V clone API and remains deferred.
- **WebAudio:** `resume()` clears the user-suspended flag; its absent asynchronous
  allowed-to-start promise queue is not supplied. The offline retry regression
  exercises buffer-construction validation failure, not allocator exhaustion.
- **Capture:** exact device IDs are requirements and ideal/bare IDs are
  preferences within Vox's existing device/permission model. Native device-list
  refresh IPC and permission infrastructure differ.
- **DOM/layout:** hidden-slot ancestry covers the V predicate. Accessibility JSON
  serialization is iterative, while separate accessibility-tree construction
  remains unchanged. Table spans conservatively rebuild on changed raw attribute
  values, including some changes with equal effective spans.

The textarea port also corrects the V model's initial caret placement to use the
value-change source. Construction and value assignment emit no `select`, while
explicit DOM selection APIs retain their events. The regression checks these
separately and covers typing, deletion, undo and redo.

## Validation

Validation uses Vox CI's pinned V revision
`f7f3add7af3c4615ba5dbedc06e18f76ef604346`, the C backend, a 10 GiB compiler limit,
and disabled legacy-compiler fallback. Native checks use Clang 19 and the real
platform/font/Skia bridges, HTTP/Linux compatibility adapters, JavaScriptCoreGTK,
and strict native pointer diagnostics. Build process trees are guarded at
12 GiB; focused runtime processes are guarded at 3 GiB. The coordinated native
batch uses at most two compiler jobs. LibJS broad runs use four jobs and run
sequentially by GC mode.

### JavaScript and parser

- **19 focused files / 71 test functions pass in both Boehm and no-GC modes:**
  38 successful compile/run pairs and 142 test-function executions.
- The default-GC package run initially passed 244 of 250 files; its one stale
  regex engine boundary expectation was corrected and the full 26,544-row engine
  corpus then passed. The final no-GC package run passed **245 of 250 files**.
- The remaining five failures use ICU 78.2 / Unicode 17 oracle data, whereas
  this Linux host supplies ICU 76.1 / Unicode 16.0. The affected files are
  `regex_class_corpus_test.v`, `regex_matching_corpus_test.v`,
  `regex_predicate_corpus_test.v`, `regex_property_corpus_test.v`, and
  `regex_unicode_properties_test.v`. Their sources and Unicode implementations
  are unchanged from the base. A native ICU probe verifies missing Beria_Erfe
  and older U+A7CE folding. No Unicode fixture was relaxed; see the existing
  [corpus provenance](../../libjs/PORT_STATUS.md).
- All **3,018 regex parser rows** pass in both GC modes; all **52,200 candidate
  rows** pass in their focused native audit. Only behavior-derived expected
  outputs changed: 9 parser rows, 15 engine rows and 57 candidate rows. Inputs
  are preserved; no blanket expected-output regeneration was used.
- The unchanged upstream AST corpus reports **91/100 matches**. Compiling the
  three changed parser files from the Vox base reproduces the same nine failures.
  **All 100 actual AST dumps are byte-identical before and after the ports.**
  Existing differences concern property-key scope metadata, class `this`
  metadata and `using` declaration metadata.
