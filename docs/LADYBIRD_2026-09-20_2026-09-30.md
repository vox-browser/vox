# Ladybird September 20–30, 2026 translation audit

## Scope and method

This batch reviews Ladybird `master` commits with **committer timestamps from 2026-09-20 00:00:00 UTC through 2026-09-30 23:59:59 UTC**, inclusive. The inventory contains **666 distinct commits**:

| Review interval, UTC | Inventory entries | Selected upstream commits |
| --- | ---: | ---: |
| September 20–24 | 213 | 26 |
| September 25–27 | 114 | 8 |
| September 28–30 | 339 | 14 |
| **Total** | **666** | **48** |

The review used commit metadata, titles, affected subsystems and paths, targeted production diffs, and comparison with Vox's implementation. Selected behavior changes were translated where the existing V subsystem could express them faithfully. This is an inventory-wide triage with deeper review of candidates; **it is not a claim that every production diff in all 666 commits was reviewed line by line**.

Initial comparison used Vox [fb11f20e1cbf](https://github.com/vox-browser/vox/commit/fb11f20e1cbf5e99195ee82ab61a44fe33d71585). During the review, `master` advanced through PR #52. This batch was rebased onto [29a715d1f621](https://github.com/vox-browser/vox/commit/29a715d1f6219ecfa890d4458dc1048f18d658ef), and overlapping DOM, CSS, layout, navigation, and painting changes were reviewed again.

The batch contains **45 translation commits plus one integration correction, touching 39 production files**. The integration correction compares the associated document by pointer identity when publishing an initial visibility entry, following Vox's V identity rule. It fixes a one-line owner check inherited from PR #52 and is not counted among the 48 selected September sources. The upstream and implementation counts differ because related source fixes share commits, while some translations require follow-up changes in Vox-specific paths. Documentation is committed separately.

## Port boundaries

- WebSocket size checks preserve Vox's existing 64 MiB message limit. They apply the upstream early validation and cumulative-fragment checks without increasing the limit to Ladybird's larger bound.
- The LibJS changes improve Vox's translated `libjs` module. The browser's production script host uses JavaScriptCore, so these changes do not establish a complete LibJS browser runtime.
- RSA validation covers Vox's WebCrypto verification path. The September 21 and September 29 upstream commits share one early validation change; Vox does not have a second generic LibCrypto RSA verification class.
- Selector coverage is the relevant V type/name matching behavior. Upstream Rust matcher unification is not reproduced wholesale.
- Nested marker work fixes pseudo identity and mutable style ownership. It does not add general primary-marker animation registration. The clone retains immutable snapshots and separates mutable stores.
- Substituted custom-property `revert` and `revert-layer` follow upstream's `unset` treatment. Full custom-property rollback to a lower layer or origin remains separate work.

## Deferred or inapplicable work

The review records defer the Rust retained-style, layout-run, fragment-arena, paint-record, and FFI migrations where Vox still uses different V data structures and ownership. Upstream UI-process canonical navigation/origin state, process IPC, platform frontend, custom DNS/DNSSEC, MediaServer, and native decoder changes were assessed against the corresponding Vox routes; they were not copied where those mechanisms are absent.

Specific useful work that needs a coordinated feature port remains:

- SourceBuffer append windows and audio splicing: correct playback requires leading/trailing decoded-audio discard support across the host decoder boundary. [5c5f034a47fc](https://github.com/LadybirdBrowser/ladybird/commit/5c5f034a47fc9ea5656ad996039e3549dcf6cd50), [9600572ff697](https://github.com/LadybirdBrowser/ladybird/commit/9600572ff697c441dbec889146202019ff58768d), [76bba1f07bc1](https://github.com/LadybirdBrowser/ladybird/commit/76bba1f07bc152ffd7f4a164319873a3fa6ecd9b).

[278e7bb76486](https://github.com/LadybirdBrowser/ladybird/commit/278e7bb76486827f9fe8496eb18d7609c1c30e76), [a206ac6a5435](https://github.com/LadybirdBrowser/ladybird/commit/a206ac6a54353751bf34f9769daeb5363f1b4fd5), [0663d7a76656](https://github.com/LadybirdBrowser/ladybird/commit/0663d7a766567b1fc9d31d2155f4d1dd442c1900).

## Validation and remaining limits

**Tests were explicitly skipped:** no tests were added, modified, imported, or run for this batch. Tests inherited from the new `master` base are outside this PR's diff. Source comparison and review of the translated changes are not runtime validation.

The individual module checks used this command shape under `tools/run_memory_bounded.py`:

```sh
v -b c -enable-globals -shared -check -memory-limit 10G -path '.|@vlib' MODULE
```

The combined check used a temporary `module main` entry point importing `animations`, `browsernet`, `compositor`, `css`, `dom`, `html`, `libjs`, `mediasourceextensions`, `painting`, `webassembly`, and `webcrypto`, with an empty `main()`. It used `-check` with the same backend, globals, compiler memory limit, and module path, without `-shared`. After rebasing, its final run reached the 6 GiB guard in approximately 45 seconds; **it is not a successful whole-project compiler check**. The earlier base's missing `EmbeddedDocument` iframe-load methods were corrected by PR #52, rather than by these September translations.

The managed commit hooks requested production rebuilds, but no completed production-build receipt was obtained. A complete browser build, linking, and browser runtime behavior have not been established by this batch.
