# Native media autoplay reflection

HTML audio/video wrappers expose HTMLMediaElement.prototype.autoplay through enumerable, configurable native getter/setter functions. Receiver branding precedes replay. The setter applies WebIDL ToBoolean without invoking author conversion hooks, including for objects and revoked proxies; an omitted argument becomes false. After replay it publishes the reflected value through the existing protected media-attribute synchronization callback, then changes the real DOM attribute through the model. True normalizes its value to an empty string; false removes it.

Publishing captured facade state before model mutation allows a fetch callback to reenter JavaScript and observe the new attribute. If that callback writes autoplay=false, its inner value survives completion of the outer setter and later dirty snapshots. Public attribute methods, replaced conversion globals and altered WeakMap/Reflect intrinsics do not mediate the native synchronization path. Replay exceptions retain their JavaScript identity, and runtime/host close releases the retained callback and owner records.

The V model reads autoplay from its live DOM owner, with the existing boolean fallback for ownerless models. Initial model setup preserves parsed nonempty attribute values. Unnamespaced autoplay changes notify only an already-existing HTML audio/video model; parsing attribute scans do not create media state, and namespaced or SVG attributes do not trigger this path. Adoption installs the notification hook in the destination document. Eligibility and playback permission therefore consult the current document's origin policy and sandbox flags.

Adding autoplay to a paused automatic preload="none" selection resumes fetching once when policy and sandbox checks permit it. Direct DOM changes reach that existing selection through the document hook.
