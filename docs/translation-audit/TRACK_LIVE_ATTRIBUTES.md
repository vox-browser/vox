# Live text-track content attributes

Once an HTML track's lazy model exists, ordinary DOM changes to its null-namespace `kind`, `label`, `srclang`, `id` and `src` attributes now reach that same model. Previously, callers had to invoke the concrete HTML attribute-change hook separately. The element now carries an optional callback installed when its model is created. `Element.run_attribute_change_steps()` runs the base attribute steps and then calls that callback for the five supported content attributes. Unmaterialized track owners remain lazy, foreign-namespace attributes remain isolated, and model and TextTrack identities stay stable. The exported concrete hook uses the same model-update helper without recursively entering the DOM dispatcher.

Setting or removing metadata updates the track's kind, label, language and identifier, including restoration of the ordinary defaults after removal. NamedNodeMap replacement and removal enter the same DOM notification path. A source assignment refreshes the model's base URL from its actual element's current document before resolving the value. The callback stays on the element during adoption, so later relative source assignments use the new document; assigning an unchanged relative string can select a different resolved URL after the document base changes. Equal resolved URLs retain the existing suppression of duplicate processing. An empty source uses the existing no-fetch error transition and can recover on a later nonempty source.

Removing `src` continues to leave the previously selected track URL in place, matching the existing concrete hook and the pinned upstream implementation's early return for an absent value. This slice adds neither cue clearing nor fetch cancellation. It also does not automate insertion: the existing concrete insertion hook is still invoked explicitly when track processing is required.
