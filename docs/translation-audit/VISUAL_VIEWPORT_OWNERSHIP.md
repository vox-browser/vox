# VisualViewport document ownership

DN-15's DOM VisualViewport facade now retains the actual CSS VisualViewport record. The reference is Ladybird `963d46a829f3e1b79f44dba9d02afb70654300fa`, `CSS/VisualViewport.{h,cpp}`, `DOM/Document.cpp:6328–6333`, and `HTML/Window.cpp:1700–1709`. The upstream checkout was read-only.

Document lazily creates and retains one concrete CSS object through the DOM/CSS interface and factory ABI. Its GC edge visits that record. Window returns the same document object while the document is fully active and otherwise returns null; its separate VisualViewport cache has been removed. The facade forwards source getters and event-handler attributes to the actual record and exposes that record's EventTarget. Creating the document object before attaching a Window preserves its identity and resolves its relevant global through the associated document.

Three committed-layout tests pass with default GC and `-gc none`. They verify construction before Window attachment, actual record/global identity, live layout/zoom/page-coordinate getters, inactive-document getter gating without changing scale or identity, event-handler identity, coalesced pending scroll events, and reset scroll/scrollend dispatch on the same EventTarget. Six existing Window cases and five smooth-scroll cases also pass with `-gc none`.

This slice centralizes the public typed facade; it does not claim complete VisualViewport parity. Document resize/initial-visibility tracking of visual scale and dimensions remains a separate source slice. The existing CSS viewport mutation path still has incomplete accumulated painting-context/repaint handoff, and the source itself retains classic-scrollbar exclusion FIXMEs. Compositor transport, remote/process boundaries, compact JavaScript exposure, and full runtime/GC bindings remain explicit. DOM-only builds without CSS fail explicitly when requesting VisualViewport instead of manufacturing empty viewport state; existing CSS-only standalone geometry adapters are unchanged.
