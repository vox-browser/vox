# Remove audio tracks in live-list order and refresh emptied controls

`AudioTrackList.remove_all_tracks()` now disables each member while the full list and that member's backlink remain available, detaches it after the queue/backend callbacks return, and clears storage after the complete traversal. Previously, storage was cleared first, so the first backend update could not observe another enabled member that remained to be disabled. Earlier members remain in storage with cleared backlinks until traversal finishes. Equal-value guards keep disabled members and repeated empty removal silent.

The routine no longer synthesizes synchronous `removetrack` events. Existing factory hooks still queue trusted `change` events for enabled members, capturing the list and creating media owner; those tasks deliver after removal against the empty list. The controls `emptied` handler now refreshes the volume/mute indicator, matching upstream, so a real load/reset refreshes the controls when its queued `emptied` event arrives. Direct forgetting remains synchronous and does not fabricate a removal event to refresh controls.
