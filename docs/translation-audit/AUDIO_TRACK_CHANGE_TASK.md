# Queue factory audio-track changes on the owning media element

Tracks created by `HTMLMediaElement.on_audio_track_added()` now queue trusted `change` events at their current `AudioTrackList` when enabled state changes. The factory previously supplied a no-op queue callback. A private list-aware hook captures the list for each transition and queues delivery on the creating media element's task source. The event uses that owner's current settings-relative timestamp at delivery; owners without settings retain the existing DOM monotonic fallback.

The factory retains its media owner and installs the hook before list insertion and initial enable. `AudioTrack.set_enabled()` commits the new state before queueing, then calls the backend, matching upstream ordering. The existing public `fn()` callback API remains available through the fallback branch. Equal-value writes return early; detached state changes queue no list event while retaining the existing backend callback behavior. Audio tracks remain independently enabled, and reassociation preserves the creating media owner while each pending event retains its captured list.
