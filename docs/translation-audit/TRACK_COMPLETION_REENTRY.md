# Preserve track source changes made by completion listeners

Translated track `load` and `error` listeners can now select another source during synchronous completion dispatch. Previously, the processing model entered its wait-for-a-new-URL state after dispatching the completion event. A listener's changed `src` could therefore update the selected URL without starting its replacement fetch. That update had already happened when the outer completion finally armed the wait, leaving the new source unprocessed.

The success and failure paths now call `track_became_ready()` after setting their terminal readiness state and before firing their completion event. Completion dispatch is the final operation in each path: no outer bookkeeping runs afterward to overwrite state established by a nested source change. A listener can consequently start and finish the next controlled load or failure while the outer event is still being dispatched. Later listeners for that outer event observe the then-current track state, which may already be the nested completion's result. This slice does not provide an event-time snapshot of readiness or cues.

The change retains the actual DOM event target introduced by the preceding slice, the stable text-track and cue-list objects, source-change cue clearing, equal-URL fetch suppression, standalone-owner independence and current synchronous event delivery. It does not alter the fetch hook, readiness-observer notification or cancellation model. Reentry from a fetch hook or a readiness observer remains outside this fix, as do stale completion protection and request generations.
