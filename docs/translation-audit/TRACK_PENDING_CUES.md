# Stop pending track resources from adding cues after source clearing

A source write or actual source-attribute removal during a translated synchronous track fetch now prevents that pending resource from adding parsed cues afterward. The earlier source-clearing change emptied the live cue list immediately, but an unchanged resolved URL or a removed attribute retained the current processing invocation. Its eventual successful response could therefore repopulate the list that had just been cleared.

The model now increments a separate source-cue generation whenever its source-clearing path runs. Both `set_src()` and the null-namespace DOM source-removal hook use that path, retaining the existing cue-list object and detaching cleared cues through `TextTrack.clear_cues()`. Each fetch invocation captures the cue generation immediately before calling its controlled fetch hook. A valid response adds its parsed cues only if that generation still matches. This does not clear the list again when the response returns, so a manual cue added after the source clear survives.

The processing-generation guards still reject an obsolete invocation after a changed resolved URL starts a replacement. For a same-effective-URL write or source removal that starts no replacement, the existing response status and WebVTT format classification, readiness transition, completion event and processing flags remain unchanged. Equal resolved URLs still suppress duplicate fetches, while removal retains the selected model URL. Removing an attribute that was already absent does not invoke a new attribute-removal hook. Foreign-namespace and unrelated attribute changes do not enter the source-clearing path.
