# Source MemoryBuffer resize invariant in production

Pinned `AbstractMachine.cpp:230–250` requires new_size >= m_size before accessing PrimitiveStorage. The ordinary V assertion was stripped in production. A genuine buffer allocated at 16 bytes was allowed to shrink to8 and return. `Build/audit-fixes/source-memory-resize-guard-original-production-gc-none.log` preserves 1/1 FAIL in 14.245 s with the return marker; this is an actual allocation and resize, not a simulated buffer.

An explicit fatal guard now preserves Source VERIFY before the unchanged resize/reserve, capacity, size and storage-offset updates. Compiled subprocesses verify the shrink rejection. Real storage checks cover empty/equal-size calls and growth both within and beyond existing capacity, preserving old bytes and zeroing the grown tail while retaining the storage handle. Growth may relocate the backing memory: an initial test incorrectly required address identity across growth and failed in both modes; those diagnostic logs are retained as `source-memory-resize-guard-initial-{production-gc-none,gc-none}.log`. The corrected test requires address identity only at equal size and verifies actual bytes through each refreshed address.

Corrected private production GC-none 1/1 PASS in 12.348 s and ordinary GC-none focused/existing buffer2/2 PASS in 7.747 s are recorded in `source-memory-resize-guard-production-gc-none.log` and `source-memory-resize-guard-gc-none.log`. This adds the 110th Wasm file outside frozen 103-file/native evidence. The capacity overload, other invariants and full runtime/collector ownership remain separate work.
