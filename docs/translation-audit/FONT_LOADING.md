Document font loaders now retain an actual Fetch controller, use source stylesheet/document URL and origin information, request the font destination with CORS, and wait for response-body consumption. Concurrent subscribers share the source loader. An ongoing controller prevents consuming a fallback prematurely. Network, CORS, body and decoder failures advance to the next source; a settled loader keeps its final typeface and unused sources. Fonts requested for rendering retain one document load-event delay, released before subscriber notification. Subscribers publish their complete FontFace descriptors and own cache invalidation.

FontFaceSet loading follows the source deferred-invoke boundary, matches fonts during that deferred step, queues an owning font-loading task, and waits for the retained FontFace status Promises. Its returned Promise uses the document's existing realm and microtask adapter. Empty matches and syntax failures follow their respective source steps.

Document-owned FontFace construction retains the source owner independently of set membership. Binary bytes are copied during binding conversion, then the source's first font-loading task starts loading and its second task publishes decoding success or failure. Status Promises keep their native capability identity. Invalid descriptors and binary data retain actual handled SyntaxError records; URL failure retains its NetworkError record. CSS-connected faces create their status Promise lazily when it is exposed, while rendering can start their load without materializing a script-visible Promise.

The compact JavaScriptCore binding now stores actual FontFace/FontFaceSet records and actual engine Promises. It preserves the original wrapper across constructor, loaded/load, set iteration, ready and load results. BufferSource conversion copies the supplied typed view's byte range, and string/dictionary conversions preserve original author-thrown values. Setlike caches follow native source membership and order hooks. DOMException wrappers retain the exact native exception record and original Promise rejection identity; no JSON value or dictionary serves as an exception or font object.

Native browsing-context creation and browser navigation now follow the source owner graph: create the actual Window/realm/settings, construct the Document and its FontFaceSet in that existing realm, associate the same Window, then parse. Font-set allocation runs inside the source temporary execution context before DOM initialization or parser-created CSS resources. Navigation retains the actual browsing-context and WindowProxy; only an initial about:blank with the same origin-domain reuses its Window/realm. Other replacements get a fresh owner. The outgoing documents retain their original font records and Promise capabilities. Window settings read their associated document’s time origin dynamically, including the initial document’s later-published navigation-start record.

The typed `Document.fonts()` getter retains the actual CSS FontFaceSet through the DOM/CSS interface boundary. It returns the same record, ready Promise and EventTarget as styling and the compact binding; a replacement StyleComputer retains that set and its original FontComputer. DOM cell visitation traces the concrete record rather than an empty DOM placeholder.

FontFaceSet inherits the native DOM EventTarget binding. Listener callbacks retain their original JavaScript object identity and stored incumbent settings; source preparation, cleanup, execution gates and exception reporting run in the owning realm. Native source events retain target/currentTarget identities and dispatcher flags. FontFaceSetLoadEvent embeds its actual Event base, traces the retained fonts, uses the owning global's relative timestamp, and exposes a stable frozen array of original FontFace wrappers. Loading, loadingdone and loadingerror listeners and handler attributes receive that native event, including source membership filtering.

An already fulfilled ready getter flushes source style/layout before returning its current slot. A newly deferred load replaces that slot with a pending Promise. The loaded transition similarly flushes layout and exits if another load starts. The source post-render checkpoint gates completion on document loading, outstanding stylesheet requests/imports and stale layout; stylesheet request delayers maintain the actual pending-request counter.

Font decoding trusts a font MIME declaration and otherwise uses font-context sniffing, including the source null result when no signature matches. Format dispatch follows `FontLoading.cpp`, including `font/x-woff`, the no-MIME decoder order, and WOFF2's MIME-or-signature preparation rule. The former CoreGraphics table reconstruction has been removed. WOFF now follows the source validation, zlib decompression, directory records and offset calculations. WOFF2 uses `gfxfont/woff2.v`, a pure V port of Google's woff2 1.0.2 decoder (`woff2_dec.cc` and its helpers) on vlib's V Brotli decoder, behind the source `WOFF2ByteBufferOut` growable-output interface. It reproduces libwoff2's sfnt bytes exactly for 97 local WOFF2 files (93 converted, the same 4 rejected) under both the C and FastC backends, ignores bytes after the Brotli stream as `BrotliDecoderDecompress` does, and tolerates the upstream incorrect-declared-sfnt-size fixture. Prepared bytes are validated through the actual source Skia font-manager call and retained verbatim for V's file-backed metrics and shaping boundary.

WOFF2 preparation uses the source shared pool: four persistent `Pool/N` workers, eight-MiB stacks, a synchronized FIFO, condition signaling and the one-second idle-collection transition. The callback remains rooted in an origin-owned record while workers receive bytes and an opaque callback identity. Completion is posted to the captured native origin loop; typeface publication, fallback and document tasks run there. Native macOS delivery uses CoreFoundation's run-loop posting and wakeup ABI. Worker-idle allocator collection maps to V's `gc_collect()` entry point; upstream uses mimalloc's `ak_kmalloc_collect()`. With `-gc none`, collection follows V's disabled-collector behavior. Allocator parity is not asserted.

The browser installs one process-owned curl font transport. HTTP response bodies remain streamed; file loading remains deferred. Native initialization failure is reported and terminates startup. An unavailable installed host rejects through Fetch instead of substituting synchronous file loading. Navigation installs the final response origin before parser resource creation. CSS requests preserve typed opaque-origin identity, including the source exception permitting file-document fonts to fetch file URLs.

Response handover also preserves the default transform pull's newly created backpressure-change Promise across the standalone reaction adapter. Without that correction, a first network chunk arriving before handover stalled subsequent chunks and EOF. Buffered and live delivery now reach the owning consume-body callback.

Focused coverage includes real split-chunk HTTP and relative-file font loads; shared and settled loaders; CORS and decoder fallbacks; load-event delay release; stylesheet base/referrer/initiator handling; deferred FontFaceSet matching and owner tasks; upstream WOFF/WOFF2 valid and malformed fixtures; native Skia validation; source pool capacity; callback retention, origin-thread delivery and worker fallback. Pool, native callback and WOFF2 URL tests also run with `-gc none`.

Focused native binding coverage includes pre-DOM owning-realm construction, initial and replacement navigation identities, retained Promise capabilities, typed Document/CSS/JavaScript identity and style reinitialization, copied DataView bytes, original getter/ToString exceptions, real Promise adoption and rejection, live set iteration, constructor brands, source FontFaceSetLoadEvent conversion and frozen-array identity, actual loading-event ordering, removed-face filtering, owner callback contexts and shutdown guards. These checks run with `-gc none` as well as ordinary engine GC roots.

Remaining SP-06 boundaries: standalone DOM/string parsing and flattened DOM-only navigation callers still support the explicit late-Window adapter. If they expose a realm-zero ready Promise before attaching a Window, the adapter keeps that existing capability stable; it does not replace an already exposed Promise. These callers do not claim the native owner-first construction graph. Standalone FontFace callers retain the explicit legacy synchronous adapter. Native font bindings currently attach to a document's Window global; Worker bindings and the upstream Worker URL-font-loading FIXME remain separate boundaries. The source union converter's SharedArrayBuffer discrimination FIXME is preserved rather than inventing its missing branch. The browser still uses JavaScriptCore, not a completed LibJS runtime. The native origin-loop and RequestServer adapters are validated on macOS; no independent non-macOS callback-loop backend is claimed. The curl adapter does not establish parity with RequestServer's separate IPC, cache and DNS process implementation.
