# Asynchronous video poster Fetch lifecycle

Feature `35c487a96c71f168ee9acaf0bb51535f64784df2` adds an optional `PosterFrameFetchTransport` containing the existing typed Fetch host and an explicit encoded-byte decoder returning the existing `DecodedImageData` interface. The poster algorithm builds its Source request and load blocker as before, then enters `fetch.fetch` when this transport is installed. Typed synchronous and legacy URL callbacks remain compatible fallback adapters when no Fetch transport is installed. Setting a transport does not itself fetch or change the poster.

Pinned `HTMLVideoElement::determine_element_poster_frame` steps 1, 6 and 7 stop an old Fetch controller, fetch the request while delaying the load event, read the body, select the first decoded frame and finalize success/failure. This translation uses Fetch's existing consume-body continuation, whose reader handles pending streamed bytes and opaque internal bodies, instead of duplicating that reader in HTML. EOF reaches the explicit decoder; network/body/decoder failures and empty frame lists clear the latest poster. Non-success HTTP status alone does not reject a decodable image. A successful response without a body retains an unconditional production panic corresponding to Source's VERIFY.

Every new algorithm invocation first detaches and stops the old real controller. Generation guards cover delayed/queued results, decoder reentry and a network-stop callback that starts another poster. Completion releases only the matching poster blocker, clears its controller before paint callbacks and preserves the newest frame/request. The returned-controller guard also stops an obsolete controller when a synchronous host reenters before `fetch` returns; a finished-generation marker defensively covers completion before that return. Adoption retains the original Fetch client and owner queue while the existing poster blocker follows the current element document.

Eight new cases cover streamed multi-chunk EOF, actual client/request metadata and owner task delivery, network and late body errors, decoder failure and no frames, first-frame selection, 404 image bodies, opaque internal body reads, pending/queued cancellation and removal, decoder success/failure reentry, unrelated load blockers, adoption, actual client CSP enforcement before the host, stop-callback reentry, and synchronous host reentry through a real document. Encoded bytes and decoded bitmap records are controlled host inputs; these tests do not validate a physical codec or network server. The parent lacks the new transport API, so no parent runtime test or parity claim is made for this API addition.
