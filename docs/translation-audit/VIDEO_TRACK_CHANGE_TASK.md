# Queue factory video-track changes on the owning media element

Tracks created by `HTMLMediaElement.on_video_track_added()` now queue trusted `change` events at their current `VideoTrackList` when selection changes. Previously, the factory supplied only a no-op queue callback. A private list-aware hook receives the list at mutation time and captures it for delivery on the creating media element's task source. The event is created at delivery with the media owner's current settings-relative timestamp when settings exist. Standalone owners without settings retain the existing DOM monotonic fallback.

The factory installs the hook and retains its media owner in the track's base record before insertion and initial selection. Change is therefore queued before the backend selection update can queue resize. The existing public `fn()` callback API remains available through the fallback branch, and detached or equal-value selection writes queue no change. A track reassociated with another list keeps its creating media task owner, while each queued event keeps the list captured for that transition.
