# Use a track element's current DOM media parent

A DOM-backed track model now checks its current immediate HTML media parent when an explicit processing-model start is requested and samples that current parent's CORS setting when preparing a fetch. Previously, both decisions used the cached model parent from insertion or an explicit setter, so moving or removing the track could leave those decisions tied to an earlier audio or video element.

The lazy DOM initializer binds the model to its actual track element. A private parent lookup follows that element's live immediate parent and accepts only an HTML audio or video element. A detached track, a track under an ordinary wrapper, and a track under a foreign-namespace element named audio or video have no qualifying media parent. The start gate therefore cannot be supplied by a stale cached parent or by a manual model-parent override. Standalone models without a bound DOM element retain their explicit model-parent fallback.

The start gate and CORS sample are separate steps. The existing loading readiness notification runs between them and can move the track. CORS uses the parent present at the later fetch step; if an already-started invocation loses its media parent during that notification, it continues with no CORS rather than running a second parent gate. Existing parallel processing and source-change loops likewise retain their lifecycle behavior. This slice does not add automatic insertion/removal forwarding, abort a fetch on removal, or automatically start a newly moved track.
