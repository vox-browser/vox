# Dispatch typed addtrack events after factory initialization

Audio and video factories now fire one typed `TrackEvent` named `addtrack` at their owning track list after initial enabling or selection and kind initialization. Audio list insertion previously fired a premature event before this state existed, while both factories subsequently fired a generic event at the media element. Low-level audio insertion now only stores and associates the track, matching video insertion. The factory event carries the exact added track and uses the media owner's current settings-relative clock at synchronous dispatch; standalone owners retain the existing DOM monotonic fallback.

This follows upstream `963d46a829f3e1b79f44dba9d02afb70654300fa`, particularly `HTML/HTMLMediaElement.cpp:1969–1978,2009–2019` and `HTML/AudioTrackList.cpp:36–40`. The current upstream `TrackEvent::create()` directly invokes the base constructor, whose `isTrusted` default is false; dispatch does not promote it. This slice preserves that flag and the existing public `TrackEvent.create()`/`construct_impl()` behavior. It does not introduce a separate trusted-event adaptation. Pending media `change` tasks retain their existing trusted flags and delivery order.
