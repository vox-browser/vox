# Bound text-track indices before integer conversion

The typed indexed-property adapters for `TextTrackCueList` and `TextTrackList` now reject unsupported numeric indices before converting them to integers. Previously, a large exact integer such as `2^32` passed the integrality check and reached unchecked narrowing, which could alias slot zero; NaN and infinities also reached an unsafe floating-point-to-integer conversion. Each getter first requires a numeric value within `[0, length)`, then converts the bounded value and checks exact integrality. Valid indices retain their object identity, and negative zero continues to select index zero. Nonnumeric values retain their existing rejection behavior.

This follows the upstream indexed-property boundary: `LibJS/Runtime/PropertyKey.h:63–85` represents indices at or above `UINT32_MAX` as strings, and `LibWeb/Bindings/PlatformObject.cpp:176–182` enters indexed lookup only for an array-index property key. `HTML/TextTrackCueList.cpp:27–34` and `HTML/TextTrackList.cpp:33–40` reject unsupported indices before accessing their vectors. The V adapter still accepts its existing numeric `dom.JSValue` representation; it adds neither native JavaScript bindings nor complete JavaScript PropertyKey coercion. Numeric strings remain rejected here.
