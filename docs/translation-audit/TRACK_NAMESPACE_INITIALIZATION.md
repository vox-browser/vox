# Text-track initialization and empty-source handling

New HTML track models initialize `kind`, `label`, `srclang`, `id` and `src` only from their null-namespace content attributes. Foreign-only metadata leaves the ordinary track defaults in place, and the actual content attribute wins in either attribute order. Foreign and prefixed attributes retain their raw values, namespaces, prefixes, owners and Attr identities. This changes initial model materialization; it adds no live namespace binding or automatic track mutation notification.

An absent source no longer calls the source setter with an invented empty value. An explicitly empty source stores an empty track URL without resolving it against the document base. Track processing rejects that empty URL before URL parsing or the fetch hook, enters the existing error state, and waits for a URL change. A later nonempty URL can use the existing retry path. Resetting a loaded track to an empty source likewise avoids fetching the document URL; repeated equal empty URLs do not create another URL-change transition. Existing metadata mapping, CORS selection, URL resolution for nonempty values and WebVTT parsing remain in place.

The upstream reference is `963d46a829f3e1b79f44dba9d02afb70654300fa`. Its `HTMLTrackElement.cpp` explicitly leaves an empty source's track URL empty and fails an empty URL without fetching. Null-namespace initialization is a deliberate continuation of the translation's namespace-aware content-attribute policy: the pinned upstream attribute-change implementation branches on the local name without rejecting a non-null namespace. The lazy V model initializer has no identical upstream helper. This slice does not claim exact parity with every upstream namespace mutation path. The existing translated synchronous error/event path and successful WebVTT processing also differ from the pinned upstream's queued events and still-unimplemented track-format processing.
