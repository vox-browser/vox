# Video representation follows the playback clock

A paused video's poster/first-frame condition now reads `current_playback_position()` rather than the script-facing `current_time()`. The latter is deliberately cached within an event-loop task. When the backend clock moved away from zero in that task, painting could retain the poster; when it returned to zero, painting could retain the video representation instead of restoring the poster or first-frame fallback. Reading representation must leave the script-facing cache intact.

This follows upstream `963d46a829f3e1b79f44dba9d02afb70654300fa`, `HTML/HTMLVideoElement.cpp::current_representation()`, whose first-frame condition uses `current_playback_position()`. The existing backend clock hook and the ownerless compatibility clock remain intact. The implementation and three focused tests share `ce4f1b38f102e77eb6b925054c305909db1fb155`, parent `fe264222c889f316020d56efcd25e728d54f66ca`. The feature changes one condition in `html/media_elements.v` and adds `layout/video_playback_representation_test.v`.

The tests use a real parsed video, its retained layout and display list, and a controlled backend clock. They cover leaving a poster with script time cached at zero, returning to a poster with script time cached at seven, and returning to the first-frame fallback without a poster. All preserve the cached script time. Equal poster/video dimensions allow the tests to check retained paint changes without rebuilding layout. Assertions inspect frame-source identity, bitmap pixels, earlier immutable paint commands, retained layout identity and collection survival. These are V layout/paint tests with supplied bitmaps, not decoder or windowed-browser checks.
