# Video poster URLs use the current document

Video poster processing now resolves a nonempty poster URL through the associated element's current document. The model previously used the base URL captured by its constructor, so a later poster request after adoption or a live base change could fetch from the old location. The existing concrete attribute hook and explicit model calls now reach the document's encoding_parse_url helper. Standalone models retain their constructor URL as the fallback.

The upstream reference is `963d46a829f3e1b79f44dba9d02afb70654300fa`, specifically HTML/HTMLVideoElement.cpp:173–205. Its poster algorithm parses relative to the element's node document. This slice delegates to the existing document URL helper; that helper's shared V URL parser still uses UTF-8 and ignores legacy query encodings. It does not establish complete encoding parity.

The three new cases cover an actual DOM video adopted between documents with distinct base elements, a retained model that reprocesses its unchanged poster after base and document URL changes, and the standalone fallback. They check retained model/frame identity across adoption, exact fetched URLs including query and fragment, natural poster dimensions, absent/empty/invalid values, failure clearing, absolute URLs and unchanged media playback/resource state. The concrete attribute hook is invoked explicitly. Adoption and base changes do not themselves start another poster fetch in this slice.
