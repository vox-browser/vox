# Deselect removed video tracks before detaching them

`VideoTrackList.remove_all_tracks()` now deselects each track while its list association is still present, then detaches it. Previously, detachment made `VideoTrack.set_selected(false)` skip its change-task hook. Removing a selected track now calls that hook once; unselected tracks and repeated removals of an empty list stay silent. The playback selection is cleared while the selected track still belongs to its list, and the list is emptied after processing the tracks.

Implementation and focused tests are committed together in `47fad0e7a63f5df48e169b3390bd6f55381cec15`, parent `6b8cdbfca46e6f9827e5dd1efab82e81ba8b7326`. The three paths are `html/media_tracks.v`, `html/media_tracks_test.v` and `html/video_track_removal_test.v`. The existing selection/removal test now expects five change-task calls instead of four, including the restored selected-track removal call. Two new cases cover selected removal, unselected removal and repeated empty removal.

The ordering follows upstream `963d46a829f3e1b79f44dba9d02afb70654300fa`, `HTML/VideoTrackList.cpp:46–54`. `HTML/VideoTrack.cpp:50–79` queues change only for a selection transition while the track remains associated with its list. Both inspected source files match that upstream commit; their hashes are retained in `Build/audit-fixes/video-track-removal-upstream-reference-v1.json`.

The selected-removal fixture uses a parsed video element's actual media owner and list, with an explicitly supplied change callback that queues an owning-media task targeting the captured list. It checks membership and selection at scheduling, backend clearing after deselection, no synchronous or microtask event, one task with the owning document and media task source, and delivery after the list is empty and tracks are detached. The unselected case rejects any change/backend hook and retains track metadata and media-owner identity after removal.
