# Source memory span access invariant in production

MemoryBuffer exposes actual AK byte spans (`AbstractMachine.h:624–627`). `AK/Span.h:253–263` verifies index < m_size before returning either const or mutable access. The translated BinaryMachineBytes.at used an ordinary assertion, removed in production. Calling at 0 on an actual empty buffer span returned without the required fatal check; the returned pointer was never dereferenced. `Build/audit-fixes/source-memory-span-guard-original-production-gc-none.log` preserves 1/1 FAIL in 7.224 s and its return marker.

The Source predicate is now an explicit fatal guard before unchanged pointer arithmetic. Subprocesses verify empty and allocated exact-end rejection. Actual spans borrow live cage bytes, preserve every in-range pointer identity and expose writes through the same buffer. An initial test attempted assignment through a function-call dereference, which this older V compiler rejects; compile-only diagnostics are retained in `source-memory-span-guard-initial-{production-gc-none,gc-none}.log`. Binding the actual pointer before assignment fixed the test syntax.

Corrected private production GC-none 1/1 PASS in 8.013 s and ordinary GC-none span/buffer2/2 PASS in 6.072 s are recorded in `source-memory-span-guard-production-gc-none.log` and `source-memory-span-guard-gc-none.log`. This adds the 113th Wasm test file outside frozen 103-file/native evidence. The cage-base invariant and complete runtime/collector graph remain separate work.
