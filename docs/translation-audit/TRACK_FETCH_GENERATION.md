# Ignore obsolete synchronous text-track fetch completions

When an active track's synchronous fetch hook changes its resolved source URL, the replacement now starts immediately and the superseded fetch result is ignored. Previously, changing a URL during a fetch cleared the loading flag without starting the replacement. The outer hook's eventual result could then append the old resource's cues, replace readiness or emit a completion event after the source had already changed.

Each entry into the parallel processing steps now increments a per-model generation, marks the model as loading and clears its wait-for-a-new-URL state. A changed resolved URL restarts those steps while the track is hidden or showing and the model is either loading or waiting for a URL change. The outer invocation compares its captured generation both when its fetch hook fails and after the hook returns a response. A superseded invocation returns before processing response status, parsing cues, changing terminal readiness or dispatching a completion event. Nested replacements therefore retain their own final state when an older hook returns. A chain that returns to an earlier URL still has a newer generation.

This is response suppression around the translated synchronous fetch hook. It does not cancel backend work or provide a general asynchronous request controller. Same-effective-URL writes, source removal and mode changes to disabled during a fetch remain outside this fix. Readiness observers can also reenter before or after the guarded fetch boundary and remain outside the generation guarantee. The preceding completion-listener correction remains intact: completion dispatch is the final operation in the success and failure paths.
