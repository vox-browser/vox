# Native media error record bindings

HTML audio/video now expose the nullable readonly `HTMLMediaElement.error` getter through their native owner. A present error wraps the actual translated `html.MediaError` record; no error returns JavaScript null. Existing media getter indexes and the compact prototype hierarchy are preserved.

The Window `MediaError` interface follows pinned upstream `HTML/MediaError.{h,cpp,idl}` and `HTMLMediaElement.idl` at `963d46a829f3e1b79f44dba9d02afb70654300fa`. Its native readonly `code` and `message` getters expose the unsigned-short code and exact DOMString message. The four `MEDIA_ERR_*` constants appear on the constructor and prototype. The constructor is illegal; metadata and `Symbol.toStringTag` follow the existing native interface conventions.

Each JavaScript runtime caches one wrapper per actual error record. Repeated reads preserve identity. A saved wrapper retains its original record after the element clears or replaces its error, including inside a reentrant `load()` callback. Two runtime realms receive distinct wrappers for the same native record, and each realm rejects the other's wrapper at its native brand boundary. Author replacement of the global constructor does not replace the captured prototype. These wrappers use the existing runtime-lifetime retention model; this slice does not add complete wrapper garbage collection.

Four binding cases cover nullable/readonly metadata, receiver brand checks before compact replay and without Proxy traps, exact NUL/non-BMP/CRLF strings, all four numeric codes, actual V record identity, cross-runtime isolation, constructor replacement, original replay exceptions, and public runtime-close guards and release of protected roots. Three browser-owner cases read the actual JavaScript getter during parsed/created media failures, exercise source selection failure plus decoder/network records, preserve old wrappers across reset/replacement, and verify the error record before play promise reactions and during reentrant `load()`. Retained painting and execution-context balance are checked.

The owner tests use controlled failing fetch hooks and a controlled host task queued through the real media task source. Translated failure entry points remain synchronous. They do not establish real network/decoder callback timing. The dedicated failure algorithm retains its existing shared generic typed NotSupportedError for the captured batch; subsequent `play()` calls reject with fresh typed errors carrying the actual record message. No HTML media failure algorithm changes are introduced.
