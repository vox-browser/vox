# Resolve track sources through their current document

A DOM-backed `HTMLTrackElementModel.set_src()` now parses its supplied value through the owning track element's current node document. Previously it always used the constructor base URL, and only a DOM attribute-change adapter refreshed that cached base. Calling the model setter after a base change, adoption, or document-URL change could therefore fetch from the old location. The shared source setter now handles the document lookup, so the adapter no longer mutates the standalone fallback base.

The upstream reference is `963d46a829f3e1b79f44dba9d02afb70654300fa`, `Libraries/LibWeb/HTML/HTMLTrackElement.cpp`, source-attribute steps 2–4, and `Libraries/LibWeb/DOM/Document.cpp`'s encoding-parsing-and-serializing URL algorithm. The implementation uses the existing document URL boundary and serializes its result before installing the track URL. Ownerless models retain their explicit constructor base. Direct model setters still accept supplied source values without reflecting a DOM content attribute.

Three new cases cover a changed live base, a new document URL after base removal, actual adoption and current-parent CORS, equal resolved URL cue clearing without refetch, empty and invalid sources, and adoption plus a nested source replacement while an outer fetch returns either success or failure. They preserve model and cue-list identity, cue detachment, generation guards and final load/error state. Standalone fetching retains its constructor URL and no-CORS fallback. All three regressions fail in their test bodies on the unchanged parent without compiler errors.
