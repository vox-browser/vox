# Source Wasm Configuration ownership and operands

Reference: Ladybird `963d46a829f3e1b79f44dba9d02afb70654300fa`, `AbstractMachine/Configuration.h` and `Configuration.cpp::reset_after_invoke`, plus `AbstractMachine.h::Store` registration.

The actual Configuration owns its two existing native ValueStack regions, eight zero-initialized registers, frame/label/locals/freelist vectors, Store reference, cached owner pointers, call-record base and result scratch. Construction registers the exact Configuration pointer with the actual Store. Explicit destruction unregisters it, releases owned vectors and destroys the region owners in source member order. The existing source thread-local region pool is retained. V owners must invoke this destruction boundary once; automatic C++ noncopyability/destruction and complete collector roots are not implied.

Source operand routing runs in all four source-address modes. Register and call-record accesses borrow their actual slots; stack reads borrow the top, and taking a stack operand removes exactly one value. The mixed mode retains the source register-bit gate, stack marker and call-record offset. Call records allocate from the real second ValueStack. Source field references and ABI offsets reach actual retained records. Stored HostFunction callables now take the actual mutable Configuration instead of an opaque placeholder input.

Reset clears both stacks with source conservative-scan slack, destroys owned inner vectors, clears outer vectors while retaining capacity, zeroes registers/scratch/depth/IP and clears cached pointers. It keeps the instruction-count limit and Store registration as in source. Four focused Configuration cases cover real owner identity and region reuse, routing and mutable aliases, reset state/capacity and actual offset consumers. The complete current 71-file package passes with GC disabled; the earlier optional-expression metadata snapshot passes 69/69 in each mode. A fresh complete canonical default-GC run also passes 71/71 files (`source-configuration-full-canonical-default-recheck.log`). The preceding canonical run was interrupted at 65/71 and is retained as incomplete evidence.

Frame installation, argument-allocation reuse, unwind and CallFrameHandle, actual prepare/call/execute functions, compiled-function-table construction, module compilation coordination and roots remain open. No instruction runner, host-call result or installed compilation is manufactured here. V vector storage replaces the source inline-vector layout; native compiled consumers must use these actual V offsets when their source paths are translated.
