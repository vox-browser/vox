# Ladybird September 1–9, 2026: selective translation audit

## Scope and review method

The source window is **2026-09-01 00:00:00 UTC through 2026-09-09 23:59:59 UTC**, equivalently ending before 2026-09-10 00:00:00 UTC, using **committer timestamps**. All **946 commits** were screened by complete commit message and changed paths. The API inventory and independent git inventory matched exactly. Candidate production diffs were then compared with Vox source before selecting adaptations; metadata screening alone does not establish behavioral equivalence.

## Adaptation boundaries

The JSON changes target Vox's standalone V LibJS parser. Its input is already UTF-16, so the port avoids the upstream simdjson/UTF-8 conversion layer and preserves the existing validation and execution-budget behavior. The 128-entry cache is bounded and local to one parse; a collision performs a full raw-key comparison. These changes do not alter JavaScriptCore's JSON implementation, which remains the browser's established JavaScript runtime boundary.

WebAssembly cloning reuses Vox's existing module byte serialization and recompilation policy. It preserves object references through clone memory and the existing target-interface exposure callback. It does **not** add target-realm identity or agent-cluster enforcement. Storage encoding rejects modules through the existing method; decoding follows the upstream behavior.

Live form collections now follow their form's current tree/document and associated controls. Vox still materializes control models lazily and sorts on cache refresh. This does not implement the upstream persistent tree-ordered association vector, cached default-button optimization, or the full related named-property optimization chain.

The new grid span-group algorithm applies to the main **native policy** path. Vox's separate Chromium sizing path and supplementary orthogonal pass retain their existing algorithms. The patch therefore does not claim that every grid policy now shares the upstream sizing implementation.

The force-dark change adapts the setting to Vox's saved profile and UI2 settings surface. It applies to currently open tabs, observes profile changes in polling tab processes, invalidates retained style/paint state, and refreshes a cached document before `pageshow` on BFCache restoration. The existing force-dark paint policy supplies the rendering behavior. Source review confirmed application before initial parsing and before cached-document restoration, successful-save-only propagation, and preservation of explicit internals overrides while the saved profile value is unchanged. Native UI execution was not available in this environment.

Modulepreload keeps the existing request construction and fetch options. The new completion path queues the event and optional descendant fetching together, in that order, and discards events from superseded link fetches. Only the newly created adapters and task callbacks transfer ownership: public caller callbacks remain borrowed. Cancellation handles document retirement, module-map replacement, and reentrant completion without releasing a callback that is still executing.

The current V checker also reported a missing return in the inline iterator inherited from the newer base. A separate integration commit adds an explicit `return none` after its advancing loop in `layout/inline_level_iterator.v`. This is a compiler compatibility adjustment, not a twenty-first upstream September 1–9 port.
