# Ladybird October 1–9, 2026 translation audit

## Scope and method

Reviewed the **1,561 distinct Ladybird commits** with UTC committer timestamps
from **2026-10-01 00:00:00 through 2026-10-09 23:59:59**, inclusive. The year
matches the existing October 10–19 and October 20–31 audits in this repository.
The latest commit in the interval is [d3b18f7f7a88](https://github.com/LadybirdBrowser/ladybird/commit/d3b18f7f7a8866aad231555bdedf056b4780f564); the earliest is
[41333055fd1c](https://github.com/LadybirdBrowser/ladybird/commit/41333055fd1c02be9a73872b552e893460b9e6ca). Author dates were not used to decide membership.

All commit messages and changed paths were screened. Original implementation
diffs were compared with the corresponding V owners for the selected fixes and
shortlisted candidates. This is not a claim that every hunk of every Rust/FFI
migration was reviewed or that Vox has complete Ladybird parity. **131 commits
touch only `Tests/`, `Meta/`, or `.github/`; those did not produce changes.**

The batch contains **59 focused implementation commits translating behavior
from 61 upstream commits**, followed by this separate documentation commit.
The initial comparison used Vox `fb11f20e1cbf5e99195ee82ab61a44fe33d71585`.
During the work, PR #52 advanced `master` to
`29a715d1f6219ecfa890d4458dc1048f18d658ef`; the implementation was rebased onto
that revision and its overlapping changes were reviewed explicitly.

**Tests were skipped at the user's request. No tests or fixtures were added,
modified, or run.** Validation is limited to source review, compiler-only checks,
whitespace checks, and checking the final changed-file set.

Each row identifies the original source and the V owner. Coordinated changes

## Adaptations and integration decisions

- **Native JavaScript scope.** These changes improve Vox's translated LibJS
  modules. The browser still uses JavaScriptCore. The parser retains its V-specific
  32-call recursion limit, now with a stack-distance guard; this batch does not
  establish complete LibJS runtime or interpreter parity.
- **Allocator scope.** Fresh anonymous mappings supply zeroed pages, while reused
  small slots retain explicit zero filling. The available-slab bookkeeping is
  the independent allocator portion of a larger upstream Rust data-block
  migration. No allocator or regex performance measurements were run.
- **Stylesheet access.** Internal stylesheet consumers retain unrestricted
  `css_rules()` access so cross-origin CSS can style a document. The fallible
  checked read and insert/delete operations enforce origin cleanliness; the
  native JavaScript CSSOM bridge already guarded script reads.
- **Failed stylesheet loads.** Eligible connected links acquire an empty sheet
  before their error event. Network failures are origin-unclean. The PR #52
  distinction between the link's `type` eligibility and response MIME remains:
  an ineligible or canceled link clears its sheet and returns, including stale
  completions after a type change. Original stylesheet location, final response
  URL, MIME fallback, quirks handling, and cache metadata are preserved.
- **History provenance.** The history entry records who selected its URL and
  retains that value through cloning and JavaScript document replacement.
  Top-level replay requests use the saved initiator and browser-UI provenance;
  `Sec-Fetch-Site: none` is limited to those browser-initiated navigations.
  Vox has no separate persisted canonical-history IPC model to migrate.
- **Find and first-letter.** Window search uses its own document and selection,
  without changing find-bar state. Flat-tree boundary comparison handles slots
  and shadow hosts. First-letter invalidation asks the real layout owner through
  the existing immutable callback bridge. PR #52's independent word-selection
  callback is retained.
- **Title notifications.** PR #52 introduced live DOM title notifications while
  this batch was in progress, making the October title-coalescing fix applicable.
  Title setters batch the intermediate remove/insert notifications without
  changing DOM mutation-observer ordering; ordinary title mutations still report.
- **Accessibility scope.** Name, description, and default-role corrections are
  implemented. The native accessibility tree, its inclusion rules, IDs, actions,
  and transport remain a separate incomplete subsystem.
- **Object and advisory information.** Object document recursion uses the final
  response URL when an embedding supplies one, otherwise the requested URL.
  The current native object host decodes images only. The advisory-information
  algorithm is available in DOM; native tooltip reporting is not wired by this
  batch.
- **Media event and state ordering.** The official position refreshes `ended`;
  loop changes refresh it immediately; control scrubbing can suppress the next
  paused loop. Seeking exposes the requested time while backend positions remain
  clamped. Readiness is updated before seek/end transition events, and end events
  are separate load-generation-cancelable tasks. Pending play promises are taken
  before dispatching a potentially reentrant pause event.
- **Media transport adaptation.** Vox's resource generation identifies a load,
  rather than each range fetch. Established range-fetch failures queue a network
  error only for the still-current load. The absent upstream RemoteFetchData and
  MediaServer stream-cancellation architecture was not fabricated.
- **MSE track initialization.** A shared track is inserted into both lists before
  queued `addtrack` events. Its initial enabled/selected state is set before list
  insertion, avoiding an initial `change` event that would overtake `addtrack`.
  Source-list events use the MediaSource Window global's clock when available,
  with the existing MSE event helper as fallback; element-list events use the
  media element's clock. This does not add worker MSE support.
- **Rebase preservation.** Ordinary property-key enumeration retains PR #52's
  linear deduplication map while sorting ordinary numeric keys. Painting retains
  its local-background positioning changes. The active SVG viewBox guard became
  redundant and was dropped in favor of the newer view-specification-aware code.
